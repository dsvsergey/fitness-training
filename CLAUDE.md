## Commands

```bash
flutter pub get                          # Install dependencies
flutter run                              # Run on connected device/emulator
flutter build apk / ios / web            # Build for a platform
flutter clean                            # Clean build artifacts
flutter analyze                          # Static analysis / lint
flutter test                             # Run all tests
flutter test test/path/to/test.dart      # Run a single test file
flutter pub run build_runner build       # Regenerate code (routes, DI, serialization)
flutter pub run spider                   # Regenerate asset references (spider.yaml)
```

Whenever models, routes, or DI registrations are added or changed, run `build_runner build` before running the app.

## Architecture

Clean Architecture in three layers:

### `lib/core/` — Infrastructure
- `bloc/` — `ApplicationBloc` (`@singleton`): global auth state machine (unauthenticated → authenticated → selected trainee). Auth state is the source of truth for the current user, coaches list, and selected trainee/appointment.
- `router/` — AutoRoute config; all routes declared here, generated into `*.gr.dart`. Home route has nested children (calendar, contacts, settings).
- `dio_settings/` — Two separate Dio clients: one for the custom fitness backend, one for the Mindbody API.
- `resources/` — themes, localizations, asset references (generated by Spider). Never reference asset paths as raw strings.
- `const.dart` — API credentials and SharedPreferences key constants.

### `lib/data/` — Data / Repository layer

Two distinct API backends:
- **Fitness backend** (`repositories/fitness/`) — custom REST API; one file per resource (auth, machines, programs, workout sessions, workout appointments, coaches, trainees).
- **Mindbody API** (`repositories/mindbody_repository.dart`) — third-party fitness platform; models live under `models/mindbody/`.

Local storage:
- `repositories/hive_repository.dart` — Hive CE local DB (programs only; Hive init is currently commented out in `main.dart`).
- `repositories/preferences_repository.dart` — SharedPreferences for primitives (token, login state, etc.).

Models use `built_value` (immutable, `Built<T, TBuilder>`). Each model file defines:
- The model class with `@BuiltValueField(wireName: ...)` annotations.
- A `fromJson` / `toJson` using `dataSerializers`.
- An `.entity` extension getter on the model and a `.model` extension getter on the entity — always convert at the boundary, never pass models into domain/presentation.

### `lib/domain/` — Business logic
- `entities/` — domain models (separate from data DTOs); also use `built_value`.
- `usecases/fitness/` — one use-case class per resource; orchestrates repositories and returns entities.
- `exception/` — typed exception hierarchy (`AuthException`, `ApplicationException`, `ConnectionException`).

### `lib/presentation/` — UI
- `screens/` — one directory per feature. Features with their own BLoC put it in a `bloc/` subdirectory (event/state/bloc files using `part` directives).
- `widgets/` — shared reusable components.
- BLoCs resolve use-cases via `GetIt.I<UseCase>()` directly at call time (not constructor-injected).
- `ApplicationBloc` is provided at the app root; feature BLoCs are provided at the screen level via `BlocProvider`.

## Key patterns

| Concern | Approach |
|---|---|
| State management | `flutter_bloc` (BLoC pattern) |
| Navigation | `auto_route` — type-safe, nested routes |
| Dependency injection | `get_it` + `injectable` (`@singleton`, `@lazySingleton`, `@injectable`); `configureDependencies()` called in `main.dart` |
| Serialization | `built_value` / `built_collection` — never hand-write `fromJson`/`toJson` for models |
| Model↔Entity | Extension getters (`.entity` on models, `.model` on entities) — convert at the data/domain boundary |
| HTTP | `Dio`; two clients (fitness backend + Mindbody) |
| Local DB | `hive_ce` for structured local data; `SharedPreferences` for primitives |
| Responsive sizing | `flutter_screenutil` — use `.w`, `.h`, `.sp` extension methods |
| Assets | Spider-generated class in `lib/core/resources/`; never reference asset paths as raw strings |
| Localization | ARB files under `lib/l10n/`; access via `AppLocalizations.of(context)` |
| UI components | `forui` component library (in addition to Material widgets) |

## Code generation files

The following are generated — do not edit manually:
- `*.g.dart` — built_value serializers and Hive CE adapters
- `*.gr.dart` — auto_route route classes
- `*.config.dart` — injectable DI registrations
