## Commands

```bash
flutter pub get                          # Install dependencies
flutter run                              # Run on connected device/emulator
flutter build apk / ios / web            # Build for a platform
flutter clean                            # Clean build artifacts
flutter analyze                          # Static analysis / lint
flutter test                             # Run all tests
flutter test test/path/to/test.dart      # Run a single test file
flutter pub run build_runner build       # Regenerate code (routes, DI, serialization)
flutter pub run spider                   # Regenerate asset references (spider.yaml)
```

Whenever models, routes, or DI registrations are added or changed, run `build_runner build` before running the app.

## Architecture

Clean Architecture in three layers:

### `lib/core/` — Infrastructure
- `bloc/` — `ApplicationBloc`: global auth state machine (unauthenticated → authenticated)
- `router/` — AutoRoute config; all routes declared here, generated into `*.gr.dart`
- `dio_settings/` — Dio HTTP client setup with interceptors
- `resources/` — themes, localizations, asset references (generated by Spider)
- `const.dart` — API base URL and credentials

### `lib/data/` — Data / Repository layer
- `repositories/fitness/` — concrete repository implementations calling Dio (one file per resource: auth, machines, programs, workouts, etc.)
- `repositories/hive_repository.dart` — local Hive DB access
- `repositories/preferences_repository.dart` — SharedPreferences wrapper
- `models/` — DTO classes using `built_value` (immutable, with JSON serialization generated via `build_runner`)

### `lib/domain/` — Business logic
- `entities/` — domain models passed between layers (separate from data DTOs)
- `usecases/fitness/` — one use-case class per feature area; orchestrates repositories → entities
- `exception/` — typed exception hierarchy

### `lib/presentation/` — UI
- `screens/` — one directory per feature (calendar, contacts, programs, machines_program, settings, stopwatch_timer, metronome, …)
- `widgets/` — shared reusable components
- Each screen/feature owns its own BLoC; BLoCs are provided at the screen level via `BlocProvider`

## Key patterns

| Concern | Approach |
|---|---|
| State management | `flutter_bloc` (BLoC pattern) |
| Navigation | `auto_route` — type-safe, nested routes |
| Dependency injection | `get_it` + `injectable` annotations; `configureDependencies()` called in `main.dart` |
| Serialization | `built_value` / `built_collection` — never hand-write `fromJson`/`toJson` for models |
| HTTP | `Dio`; repositories inject `Dio` from the service locator |
| Local DB | `Hive` for structured local data; `SharedPreferences` for primitives |
| Responsive sizing | `flutter_screenutil` — use `.w`, `.h`, `.sp` extension methods |
| Assets | Spider-generated class in `lib/core/resources/`; never reference asset paths as raw strings |
| Localization | ARB files under `lib/l10n/`; access via `AppLocalizations.of(context)` |

## Code generation files

The following are generated — do not edit manually:
- `*.g.dart` — built_value serializers
- `*.gr.dart` — auto_route route classes
- `*.config.dart` — injectable DI registrations
